# Feature availability and boundaries

Generated from `docs/features.json`. This describes the dashboard integration, not every capability of upstream PC². A setting does not install its external runtime.

**Status key:** Available = integrated controls within the stated limits; Read-only = inspection only; Partly supported = only the listed scope; Requires external setup = separately deployed services; Not yet validated = no deployment certification; Unavailable = not provided here.

| Feature | Status | What works | Limits / next step |
| --- | --- | --- | --- |
| PC² Accounts & Permissions | Available | Create/edit native identities, metadata and permission checkboxes; generate/import credentials. | Creating a judge account does not start its service. Managed service accounts remain protected. Use individual accounts; start the deployed service through its lifecycle. |
| Languages & Compilers | Partly supported | Manage language definitions; choose existing isolated C++17/C++20/Python profiles. | Additional languages need a compiler/runtime and trusted sandbox profile. Saving a definition alone does not install them. Deploy and validate the language inside the isolated judge before enabling it. |
| Problem settings | Available | Edit native problem identity, limits, flags, validator settings and balloon color. | Only deployed isolated execution/validator policy may be active; test replacement does not rejudge. Use trusted deployment for custom executables. |
| Groups & Divisions | Available | Create/edit group names, native IDs, scoreboard visibility and account membership. | Group visibility controls do not replace private/public scoreboard freeze rules. Review membership and both scoreboard views before the event. |
| Clarification Categories | Available | Create/edit active clarification categories used by the native contest. | A category is a question-routing definition; it is not an announcement or an answer. Use Questions & announcements to send messages to teams. |
| Judgement Definitions | Available | Create/edit verdict names, acronyms and active state. Native Accepted remains protected. | A new verdict definition does not change a submission or add execution detection. Use the pending review queue for decisions and deployed judge support for detection. |
| Automatic Judge Clients | Requires external setup | Configure enabled judge accounts and native problem filters. | The corresponding isolated judge process must already be deployed; settings do not create services. Provision the documented VM and start the judge lifecycle. |
| Contest & Team Display | Available | Edit native contest title, short name, team display, login policy and advanced flags. | Configuration changes do not activate a separate contest or certify imported settings. Use Contests for independent events, and Clock & schedule for event timing. |
| Scoring Rules | Available | Read/edit the installed native scoring properties, including penalties and freeze behavior. | These controls use the installed scoring implementation; they do not deploy arbitrary scoring plugins. Rehearse ties, pending approvals and public freeze before changing official rules. |
| Site Clocks | Available | Inspect/edit native site clocks and explicitly start/pause their configured scope. | Changing elapsed time affects official event timing; server activation and clock start are separate. Review the site scope and schedule; pause before planned infrastructure changes. |
| Sites | Requires external setup | Edit permitted native sites and connection settings; protected local loopback remains fixed. | Each remote site needs a separately configured PC² server and private credentials. Provision/test the remote site using native deployment procedures. |
| Verdict Notifications | Available | Configure per-problem final-verdict suppression and cutoff rules. | Preliminary verdict delivery must remain suppressed by the judging workflow policy. Use announcements for general messages; approve held results from Submissions. |
| Balloon Settings | Requires external setup | Configure native balloon printing/mail settings. | Printer drivers, devices, SMTP service and delivery need separate setup; no installation or test-mail guarantee. Use Problems for colors and Balloon delivery for acknowledgements; validate external delivery. |
| Balloon Delivery | Available | List final accepted team/problem entries and confirm delivered or pending in one dialog. | Acknowledgement records organizer intent, not proof of physical handover. Hidden diagnostic teams are excluded. Arrange physical balloon distribution separately. |
| Finalization & Medals | Available | Edit native medal rank thresholds, certification state and comment. | Certification does not resolve pending judgements or produce an institution-approved certificate design. Finalize decisions and verify standings before certifying; export the needed summaries. |
| Native Profiles | Available | Edit existing native profile name, description and contest ID metadata. | This is not a full desktop profile-switching interface or a clone of linked dashboard state. Use Contests to create, clone, activate and archive independent managed events. |
| Connections | Available | Inspect native client/site connections and disconnect permitted non-runtime connections. | Critical runtime clients are protected. Native connections are not a router device inventory. Use Team connections for observed browser presence; use router tools for network inventory. |
| Native Reports | Partly supported | Generate supported native text reports with filters and owner reauthentication. | Desktop file-only native report exporters need the desktop alternative. CSV/PDF summaries are not full recovery archives. Use the stated native desktop export or Exports & Backups as appropriate. |
| Submission Management | Available | Filter submissions, adjust permitted elapsed times, recoverably remove/restore and release checkouts; request guarded rejudging. | Rejudging can execute code and change official results. Bulk actions can partially complete after a connection failure. Inspect actual state before retrying; use submission details for final-verdict review. |
| Clarification Management | Available | Inspect native questions, deletion/recovery and checkout state; send answers and announcements from the main page. | Private/all-team audiences must be chosen deliberately; removal does not unsend a message already read. Check the recipient scope and retained question before confirming. |
| Private Judge Data | Available | Inspect current private input/expected output and replace supported problem test pairs. | Replacing current tests does not rejudge old attempts or reconstruct historical test revisions. Keep a separate data revision archive and request an explicit rejudge when justified. |
| Account Generation & Import | Available | Preview and generate/import native accounts with group membership and credential export. | Generated credentials are private; creating judge/site identities does not provision services. Use synthetic accounts for rehearsal and distribute real credentials privately. |
| Compare Source Files | Available | Compare two retained source files without executing them. | Text similarity is not proof of correctness, plagiarism or algorithmic equivalence. Inspect source and retained evidence with qualified human judgement. |
| Submit on Behalf of a Team | Available | Owner can submit for an active team/problem while the clock runs. | Creates an official attempt and can execute code through the isolated judge; requires reauthentication. Prefer the hidden diagnostic team for a rehearsal. |
| Contest Playback | Available | Import validated native playback data and explicitly start/stop it. | Only an empty technical contest; native playback starts clocks and continues after the browser closes. Use an independent rehearsal; never replay into a real event. |
| Event Feeds | Read-only | Inspect retained/native Event Feed definitions and status. | The installed upstream add/update handlers are unimplemented; this dashboard does not claim they work. Use supported native JSON/XML report exports, or contribute a tested upstream implementation. |
| Input Validation Results | Read-only | Read saved native input-validation results. | Arbitrary uploaded custom validators are not executed on the organizer host. Deploy trusted isolated validator support and validate it separately. |
| Shadow CCS Status | Read-only | Inspect Shadow CCS state and existing imported-event information. | External CCS credentials/connection are not provisioned here. Use the original native tools and a separately tested external CCS deployment. |
| Installed Java Plugins | Read-only | List installed Java plugins and their native classes. | No arbitrary JVM plugin installation, Swing windows or graphical print dialogs in the web dashboard. Use native PC² Administrator and trusted host deployment for supported plugins. |
| Service Logs | Available | Read bounded/redacted tails of known service logs. | Only supported files; log contents are not proof that every external service succeeded. Use trusted host diagnostics for deeper infrastructure inspection. |
| Reset & Recovery | Available | Reset through the guarded native workflow. | Requires full backup, exact event identity, owner reauthentication and explicit destructive confirmation. Prefer a new independent contest for a new event. |
| Feature Coverage | Available | Show capability status and explicit limits in this section. | This is an integration map, not parity with every upstream desktop dialog. Read the User Guide, Installation and Roadmap. |
| Organizer operating systems | Not yet validated | Current deployment: macOS Apple Silicon with Lima VZ Linux ARM64 judge. | This overlay is not certified on Windows/Linux organizer hosts or Intel Macs. Contribute isolated host support and run clean-machine acceptance. |
| One-click installer and fresh-host recovery | Not yet validated | Engineer-assisted setup and consistent contest backups to a new workspace. | No fully validated one-click clean-machine installer or full host/VM disk restore. Follow Installation and rehearse the whole deployment and recovery. |
| Historic test revisions and peak memory | Unavailable | Current reference tests, retained native evidence and available execution times. | No guaranteed historic dataset reconstruction or trusted peak memory metric. Use clearly labelled current-data learning replay; do not invent historical evidence. |
| Public cloud and multiple tenants | Not yet validated | Private-LAN local organizer architecture with optional approved HTTPS admins. | Not a certified public Internet service or multi-university tenancy layer. Separate threat model, deployment and independent security/load review. |
| Router device inventory | Unavailable | Observed browser presence, verified session events and connection gaps. | Cannot identify every router-connected device or prove uninterrupted physical network presence. Use router administration for hardware inventory with an appropriate privacy policy. |
| Team Learning Reports | Available | Private per-active-team PDFs/ZIPs, source, statements and current-data isolated replay. | Only deployed C++17/C++20/Python replay; expensive for large datasets and deliberate solution/test disclosure. Generate after the event, validate capacity and give each team only its own archive. |

See [Installation](INSTALLATION.md), [Roadmap](ROADMAP.md) and [User Guide](USER_GUIDE.md). A local regression pass does not certify every host, LAN or load.
