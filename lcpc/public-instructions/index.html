Getting Started

Use the contest address and team account supplied by the organizers. After signing in, confirm the team number shown at the top of the dashboard. Keep using the same contest address throughout the session.

Open Problem PDFs from the main platform to read individual statements or download the complete booklet. Check each problem's input format, required output, constraints, time limit and memory limit. Passing the examples alone does not guarantee that a solution will pass all judge tests.

Follow the organizing committee's announced schedule, permitted languages, allowed resources and event-specific rules. These instructions explain how to use the platform; the committee provides the rules for each contest.

Preparing and Submitting a Solution

  1. Prepare the source file and try it locally with the examples and relevant edge cases. Match the required output exactly, without additional prompts or explanatory text.
  2. In Runs, click Submit Problem. Select the correct problem and one of the languages offered for the contest.
  3. Attach your source file: .cpp for C++ or .py for Python. Submit one source file, rather than a PDF statement, executable, folder or archive.
  4. Check the selected problem, language and file before confirming the submission. Choosing the wrong problem or language can cause a valid solution to fail.
  5. Wait for the submission confirmation and check its entry in Runs. Follow the verdict there until judging finishes.

If an upload fails or the connection is interrupted, check whether the submission already appears in Runs before sending it again. After an unsuccessful verdict, review the cause and correct the solution before submitting a new attempt.

Reading Submission Results

Each entry identifies the problem, language, submission time and verdict. Use the filters to find an attempt; Clear Filters restores the full list. Filters change only what you see.

Pending / JudgingThe submission is waiting or being processed. This is not a final verdict; wait for judging to finish.

AcceptedThe solution passed the judge's tests and the problem is counted as solved.

Wrong AnswerThe output was incorrect on at least one test. Review the logic, edge cases and required output format.

Compilation ErrorThe judge could not compile the source. Check the chosen language, syntax and required libraries.

Runtime ErrorThe program failed while running. Check invalid memory access, division by zero and other execution errors.

Time Limit ExceededThe program exceeded the allowed running time. Review complexity and possible infinite loops.

Memory Limit ExceededThe program exceeded the allowed memory. Review large allocations and data structures.

Output Limit ExceededThe program produced too much output. Check repeated printing and loops.

Scoreboard, Clarifications and Help

Scoreboard summarizes team rankings, solved problems and penalty. A problem cell shows a solved, pending or unsolved state, with attempts or solution time where applicable. Read the exact verdict for your own submission in Runs. Rankings and penalties follow the contest settings; public standings may be frozen near the end.

Use Clarifications for questions about a statement or contest procedure. Select the relevant problem and write a clear question, then check the reply and any general announcements. Report an unclear statement to the judges rather than assuming a different requirement.

If the interface stops updating, check your connection and refresh the main platform. If asked to sign in, use your team's account and check the existing attempts before resubmitting anything. For a persistent issue, notify an organizer with the problem, submission identifier if available, and the error shown.

Instructions and PDFs open in separate tabs. Keep the original team dashboard open and return to it to submit solutions, follow results or contact the judges.

قبل البدء

استخدم رابط المسابقة وحساب الفريق اللذين تسلّمتهما من اللجنة المنظمة. بعد تسجيل الدخول، تأكد من رقم الفريق الظاهر أعلى الواجهة، واستمر في استخدام الرابط نفسه طوال الجلسة.

افتح Problem PDFs من المنصة الرئيسية لقراءة ملفات المسائل أو تنزيل الكتيب كاملًا. راجع صيغة الإدخال والإخراج والقيود وحدود الزمن والذاكرة لكل مسألة. اجتياز الأمثلة وحده لا يضمن اجتياز جميع اختبارات التحكيم.

التزم بالمواعيد واللغات والمصادر المسموحة والضوابط التي تعلنها اللجنة المنظمة. تشرح هذه الصفحة طريقة استخدام المنصة، وتحدد اللجنة قواعد كل مسابقة.

تجهيز الحل وإرساله

  1. جهّز ملف الشيفرة المصدرية وجرّبه على جهازك باستخدام الأمثلة والحالات الحدّية المناسبة. التزم بصيغة الإخراج المطلوبة دون رسائل إضافية أو شرح ضمن الناتج.
  2. من صفحة Runs اضغط Submit Problem، ثم اختر المسألة الصحيحة وإحدى لغات البرمجة المتاحة للمسابقة.
  3. أرفق ملف الشيفرة: .cpp للغة C++ أو .py للغة Python. أرسل ملفًا مصدريًا واحدًا، وليس ملف المسألة بصيغة PDF أو برنامجًا تنفيذيًا أو مجلدًا أو ملفًا مضغوطًا.
  4. راجع المسألة واللغة والملف قبل تأكيد الإرسال؛ فقد يفشل الحل الصحيح إذا أُرسل لمسألة أو لغة غير صحيحة.
  5. انتظر تأكيد الإرسال، ثم تأكد من ظهور المحاولة في Runs وتابع حالتها حتى يكتمل التحكيم.

إذا فشل الرفع أو انقطع الاتصال، تحقق أولًا من ظهور المحاولة في Runs قبل إرسالها مرة أخرى. وعند ظهور نتيجة غير مقبولة، راجع سببها وصحّح الحل قبل تقديم محاولة جديدة.

قراءة نتائج المحاولات

تعرض كل محاولة المسألة واللغة ووقت الإرسال ونتيجة التحكيم. استخدم الفلاتر للعثور على محاولة، واضغط Clear Filters لعرض القائمة كاملة. تؤثر الفلاتر على العرض فقط.

Pending / Judging — قيد الانتظار أو التحكيمالمحاولة تنتظر دورها أو يجري تنفيذ اختبارات التحكيم عليها. هذه ليست نتيجة نهائية؛ انتظر اكتمال التحكيم.

Accepted — حل مقبولاجتاز الحل اختبارات التحكيم، وتُحتسب المسألة محلولة للفريق.

Wrong Answer — إجابة خاطئةالناتج غير صحيح في اختبار واحد أو أكثر. راجع منطق الحل والحالات الحدّية وصيغة الإخراج المطلوبة.

Compilation Error — خطأ في الترجمةلم يتمكن المحكّم من ترجمة الشيفرة. راجع اللغة المختارة وصياغة الشيفرة والمكتبات المطلوبة.

Runtime Error — خطأ أثناء التنفيذتعطّل البرنامج أثناء التشغيل. راجع الوصول غير الصحيح للذاكرة والقسمة على صفر وغيرها من أخطاء التنفيذ.

Time Limit Exceeded — تجاوز الزمنتجاوز البرنامج الزمن المسموح. راجع تعقيد الخوارزمية واحتمال وجود حلقات لا تنتهي.

Memory Limit Exceeded — تجاوز الذاكرةتجاوز البرنامج الذاكرة المسموحة. راجع حجم الذاكرة المحجوزة وهياكل البيانات المستخدمة.

Output Limit Exceeded — تجاوز حجم الإخراجأنتج البرنامج مخرجات أكثر من المسموح. راجع تكرار الطباعة والحلقات.

لوحة النتائج والاستفسارات والمساعدة

تلخّص Scoreboard ترتيب الفرق وعدد المسائل المحلولة والعقوبة. وتبيّن خانة المسألة إن كانت محلولة أو قيد الانتظار أو غير محلولة، مع المحاولات أو زمن الحل بحسب الحالة. راجع Runs لمعرفة نتيجة محاولتك بالتحديد. يخضع الترتيب والعقوبات لإعدادات المسابقة، وقد تُجمّد النتائج العامة قرب النهاية.

استخدم Clarifications للاستفسار عن نص مسألة أو إجراء متعلق بالمسابقة. اختر المسألة المعنية واكتب سؤالًا واضحًا، ثم تابع الرد والإعلانات العامة. أبلغ لجنة التحكيم عن أي غموض في النص بدل افتراض متطلبات مختلفة.

إذا توقفت الواجهة عن التحديث، تحقق من الاتصال وحدّث صفحة المنصة الرئيسية. وإذا طُلب تسجيل الدخول، استخدم حساب فريقك وراجع المحاولات الموجودة قبل إعادة إرسال أي حل. عند استمرار المشكلة، أبلغ أحد المنظمين بالمسألة ورقم المحاولة إن توفر ورسالة الخطأ الظاهرة.

تفتح التعليمات وملفات المسائل في تبويبات مستقلة. أبقِ واجهة الفريق الأصلية مفتوحة، وارجع إليها لإرسال الحلول ومتابعة النتائج والتواصل مع لجنة التحكيم.
